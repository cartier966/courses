3. Where the image really lives

ChromaDB does not store the picture. It stores the searchable vector plus an address (URI) pointing to the file.

🗄️ ChromaDB record

idimg_01
descriptionA cat sitting near a window
embedding
metadata{"uri": "./images/cat.jpg", "category": "animals"}

💾 Your disk

images/\n  cat.jpg      ← the real pixels\n  raincoat.jpg\n  tree_growth.jpg

The uri is the pointer. For this class project we embed the description; a true CLIP system would embed the image itself.

4. add() vs upsert()

Rebuilding your index and getting duplicate-ID trouble? Try both methods on the same ID.

add() is for brand-new IDs and won’t update an existing record. upsert() updates if the ID exists and inserts if it’s new, so use it when rebuilding.
